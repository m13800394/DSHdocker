# MRI 项目与封装的关系

当前任务是通用 DeepSeek Harness 的容器封装、镜像版本管理和一键部署。用户已明确：模型、GPU 和远程桌面协议尚未确定，这些选择不应阻塞当前交付。

## 各部分职责

| 部分 | 职责 | 对当前封装的影响 |
| --- | --- | --- |
| Docker 镜像 | 固定 harness、依赖和启动方式 | 当前交付主体 |
| Harness | 提供模型调用、工具调用、会话和执行循环 | 使用官方固定版本 |
| MRI 专家智能体 | 根据任务和界面输出领域相关计划与检查结果 | 后续加入提示词、知识和工具配置 |
| Manager 智能体 | 分派任务、汇总结果、控制流程 | 后续单独实例与通信协议 |
| 本地模型服务 | 为智能体提供推理或图像理解能力 | 后续通过网络端点接入，不把权重写进 harness 镜像 |
| 远程桌面适配器 | 提供截图、鼠标键盘操作和结果读取 | 后续按实际协议实现 |

上游采用插件架构，模型、工具和执行循环可以独立扩展。当前选择是封装官方 npm 发布包，保留官方 Web 界面，不修改上游核心。[官方架构说明](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/docs/architecture.md)

## 后续接入方向

MRI 操作目标为“截图观察 → 任务规划 → 鼠标键盘操作 → 再次截图检查”。控制台通过远程桌面访问，模型计划在本机或服务器部署。协议、模型、硬件和业务插件均待后续阶段确定。

专家和 manager 可以共用一个基础镜像，通过不同配置成为独立容器；它们不需要各自打包一份模型权重。模型服务可独立运行并被多个实例访问。

多个智能体对同一桌面的动作应在操作接口处串行化；Docker 的文件隔离不会阻止多个实例同时操作同一远端桌面。此项属于后续操作系统设计，当前不连接远程桌面或扫描设备。

## 当前隔离范围

每个实例有独立 Compose 项目、容器、网络、配置状态卷和工作区卷。没有挂载宿主工作目录或 Docker socket。Web 端口仅发布到宿主 127.0.0.1。

上游支持多会话和进程内子智能体；本阶段实现独立 harness 实例的容器隔离，尚未实现“一容器内仅允许一个活跃模型智能体”的强制约束。跨容器 manager 调度和禁用内部派生能力需随业务编排阶段实现，不能将多个 Web 实例等同于已完成多智能体协作。
