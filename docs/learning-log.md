## 2026 年 10 月 26 日 首次运行故障与修复

**首次构建：** `0.1.0-20261026t032842z-499f87a2162b` 构建成功，但启动失败，不能视为可交付版本。

**问题一：** 原生扩展加载报错 `failed to map segment from shared object`。通过一次性容器对比确认加载器把原生库复制到 `/tmp` 后再加载，tmpfs 默认的执行限制阻止了共享库映射。与基础镜像 glibc 不兼容的初始猜测不符，因此没有切换 Debian 版本。

**修复一：** 显式设置 `/tmp:rw,exec,nosuid,nodev,size=256m`，保留只读根文件系统和非 root 用户。上游服务随后启动。

**问题二：** 服务启动但健康检查失败，匿名访问首页返回 401。读取上游认证说明，确认每进程生成登录 token，通过根地址换取签名 Cookie；这不是服务异常。

**修复二：** 包装程序捕获登录链接并写入容器 `/tmp` 的 0600 临时文件，在日志中隐藏 token。健康检查完成 Cookie 交换后验证页面。新增 `open` 和 `url` 命令用于本机访问。

**依赖处理：** npm 提示部分安装脚本未执行。构建改为显式跳过依赖安装脚本，仅执行已检查的上游 spawn-helper 权限修复，并在构建时加载关键原生模块进行验证。

**本地数据：** 读取上游文档发现会话贡献默认开启、OTel 在反馈时可上传，封装增加本地配置关闭两者。尚未调用模型或处理 MRI 数据。

**认证细节：** 实测 Web 根地址 token 交换返回 HTTP 303，而 API `/connect` 使用 302。健康检查已按 Web 根地址实际行为修正，保留 Cookie 验证；不通过关闭认证规避问题。
